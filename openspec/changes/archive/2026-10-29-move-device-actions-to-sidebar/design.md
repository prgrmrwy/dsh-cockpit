## Context

控制台的排序/启停 currently 绑定选中的 device；sidebar 每行目前是一个 button。将 more 放入行内时不能嵌套 button，且需要将操作目标显式传给处理函数。现行 shell 规范还要求操作位于详情标题行，本次同步调整。

## Goals / Non-Goals

Goals：每台设备就地操作、禁用状态可辨认、菜单键盘可用、保持输入保护。
Non-Goals：修改连接或删除语义、拖拽排序、顶部 header 改版、菜单增加删除操作。

## Decisions

- 每行改为外层容器 + 独立选择 button + 独立 more button。more 使用 16px 三点 SVG，右侧固定占位，非 hover-only，保证触屏和键盘发现；选中背景归行容器，名称截断，tag 与 more 不收缩。
- 使用一个受控菜单实例（openDeviceId），同一时间只开一个。more 带 `aria-haspopup="menu"`、`aria-expanded` 与设备专属名字；展开后聚焦首个可用项。方向键/Home/End 导航，Escape 只关菜单并归还焦点；外部点击、选择其它设备和完成操作后关闭。
- 上下移针对全量设备持久化顺序，首项上移/末项下移禁用；启停按目标 enabled 切换。即使该设备不是当前详情，也不切换详情。单飞 busy 期间禁止重复操作；错误显示在菜单所属行附近，可由辅助技术获知。
- 对当前正在编辑的设备执行启停且草稿 dirty 时，继续请求确认放弃；取消无请求，确认后仅在成功时重置其草稿。操作其它设备不影响当前草稿。排序不改变连接字段，不需丢弃草稿。
- 禁用 tag 使用既有 console 中性色令牌、紧凑圆角轮廓，无新色值；左侧状态点灰化。顶部 header 继续按 enabled 过滤，本次只补集成测试证明其不会误删。

## Risks / Trade-offs

- [菜单被 sidebar 滚动边界裁切] → 菜单定位需保证在可视边界内，短视口测试最后一行并检查全菜单可见。
- [菜单 Escape 冒泡关闭整个控制台] → 在菜单处理并停止传播，关闭后焦点回到所属 more。
- [启停其它设备误改选中设备草稿] → 以 deviceId 判断目标，增加非选中项操作单测。

## Migration Plan

纯前端构建后刷新现有 3090 页面；无数据迁移。回退只还原本次 web 修改，禁用记录不变。
