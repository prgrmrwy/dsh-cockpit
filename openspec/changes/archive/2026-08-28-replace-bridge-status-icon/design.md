## Context

动机见 `proposal.md`。当前 `TopBar.tsx` 用同一个 emoji 字符 `⛓` 表示两种桥接状态，靠 `.bridge-mark`（accent 色）与 `.bridge-hint`（dim 色 + `opacity: 0.45`）区分，字号 12px。

约束来自仓库既有不变式：颜色必须走 `app.css` 令牌或继承色，禁止写死主题色值；顶栏 tab 已声明 `flex: none` 以避免设备名被压缩，因此新图标不能引入宽度抖动；仓库倾向零运行时依赖。

## Goals / Non-Goals

**Goals:**

- 让「链接」语义在小尺寸下一眼可辨，不再被误读为暂停符。
- 两种桥接状态靠形状区分，不依赖颜色即可分辨。
- 保持既有可访问性信息、hover 说明与 `data-bridge-hint` 测试钩子不变。

**Non-Goals:**

- 不改桥接插件协议、`bridgeSeenAt` 的产生与匹配方式。
- 不改会话状态 chip、连接状态点或顶栏其它元素。
- 不引入图标库、图标字体或任何运行时依赖。
- 不新增点击行为：该标记保持纯展示 + hover 说明。

## Decisions

### 1. 内联 React SVG 组件，而不是静态资源或图标库

新增一个 `BridgeIcon` 组件，导出 `connected` 与 `disconnected` 两种形态，返回内联 `<svg>`，`stroke="currentColor"`、`fill="none"`，并接受 `size` 参数。

内联 SVG 能继承 `currentColor` 从而自动适配深浅主题，不产生额外网络请求，也不需要为 PNG 准备 1x/2x 资源。静态 PNG 无法随主题变色；引入 lucide 之类的库会为一个图标增加运行时依赖，与仓库零依赖倾向冲突。

参考用户提供的两张示意图：已连接为两段相扣的完整链条；未安装为两段分离、中间断开的链条。图形用简单的圆角矩形斜链 + 直线笔画描边表达，不做复杂细节，保证 14–16px 下仍可辨。

### 2. 尺寸提升到 14px 并用固定盒子消除跳变

图标尺寸从 12px 字符提升到 14px，`.bridge-mark` 与 `.bridge-hint` 统一设置相同的 `width`/`height` 与 `display: inline-flex`，两种状态占位完全一致。

SVG 的 `viewBox` 与外框尺寸在两种形态中保持相同，因此形状切换只改变路径、不改变盒模型，满足「无布局跳变」要求。继续保留 `flex: none`，避免在可横向滚动的 tablist 中被压缩。

### 3. 弱提示语义靠透明度而非改变颜色语义

未安装态继续使用 `var(--fg-dim)` 加降低的不透明度，保持「弱提醒、非告警」的既有产品判断；已连接态继续使用 `var(--accent)`。

形状已经承担了区分职责，颜色只负责强调层级，因此不把未安装态改成 `--warn` 或 `--error`——那会把一个可选增强渲染成故障。

### 4. 测试断言形状标记而非 SVG 路径

给两种图标分别加稳定的 `data-bridge-icon="connected" | "disconnected"` 标记，测试断言该标记、可访问名称与 hover 说明，不断言 `<path d="...">` 具体坐标。

路径数据属于视觉实现细节，锁死它会让后续微调图形必然改测试；而形状标记表达的是「呈现了哪种状态」这一用户可观察语义。

## Risks / Trade-offs

- **[手写 SVG 在极小尺寸下辨识度不足]** → 采用粗描边（约 1.8–2 stroke-width）、圆角线帽、去除内部细节；14px 下先自查，最终由用户在真实页面确认观感。
- **[图标变大后顶栏更拥挤]** → 仅从 12px 增至 14px，与相邻 StateDot（10px）和设备名保持协调；间距沿用既有 `gap`。
- **[断链图标可能被误解为故障]** → 保持 dim 色与低不透明度的弱权重，并在 hover 说明中明确这是可选插件未安装，不是设备异常。
- **[两个组件形态导致重复代码]** → 共用同一个 `viewBox` 与描边属性，仅路径不同，实现集中在单个文件内。

## Migration Plan

1. 先加图标组件与测试，再替换 `TopBar.tsx` 中的两处 emoji。
2. 调整 `.bridge-mark` / `.bridge-hint` 尺寸规则，保持颜色令牌不变。
3. 运行 `pnpm typecheck`、`pnpm test`、`pnpm lint`、`pnpm build` 与 OpenSpec 严格校验。
4. 构建后刷新现有 `http://127.0.0.1:3090/`，确认两台设备的图标形状、深浅主题表现与顶栏无跳变。
5. 回滚方式为整体回退本 change；不涉及数据、协议或注册表，无迁移成本。
