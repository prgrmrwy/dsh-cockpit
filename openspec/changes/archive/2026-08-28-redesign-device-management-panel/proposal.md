## Why

当前设备管理面板把添加表单与设备列表直接纵向堆叠，信息层级、状态可读性、操作分组和宽屏空间利用都较弱，难以快速判断设备整体健康状况或完成日常管理。需要在不改变连接与安全语义的前提下，将其重构为清晰、响应式且遵循现有深浅色主题的现代控制台。

## What Changes

- 将设备管理全屏面板调整为现代控制台结构：顶部标题与设备摘要、宽屏“设备列表 + 添加设备”双栏布局、窄屏单栏布局。
- 将每台设备呈现为结构化管理行，明确显示名称、设备类型、连接状态、必要诊断及次级标识，并区分常规操作与危险操作。
- 改进添加设备表单的信息层级：直观的本机/SSH 远端类型选择、字段说明与占位提示、明确的验证中状态和独立错误提示，同时保持失败时输入不丢失。
- 为空设备列表提供清晰的空状态和添加引导。
- 所有新增视觉值继续使用 `app.css` 主题令牌，并同时覆盖深色和系统浅色主题；不引入硬编码主题色。
- 优化顶栏选中设备 tab：保留清晰的背景与文字选中态，但移除 border 描边，降低浅色主题下的厚重感。
- 不改变设备注册、SSH 免密验证、启用/禁用、删除确认、连接状态语义或远端 DSH 行为。
- 加强仓库 OpenSpec 路由前馈：明确 UI、布局、交互、响应式、可访问性和文案语义属于用户可观察行为变化，不能因改动小、单文件或纯 CSS 绕过 change 流程。

## Capabilities

### New Capabilities

（无。）

### Modified Capabilities

- `cockpit-device-shell`: 细化设备管理面板的布局、信息层级、响应式、表单反馈、空状态及主题一致性要求，并调整顶栏选中设备 tab 为无边框选中态。

## Impact

- 规划与流程：`CLAUDE.md`（`AGENTS.md` 指向它）中的 OpenSpec 路由前馈。
- Web UI：`packages/cockpit-web/src/panels/Panels.tsx`、`packages/cockpit-web/src/styles/app.css`。
- 测试：`packages/cockpit-web/tests/` 下与设备管理面板相关的组件/结构或样式约束测试；必要时补充现有测试夹具。
- Cockpit 本机 API 与共享类型做向后兼容的增量扩展：设备事实增加可编辑连接字段，设备更新请求增加可选排序目标；远端 DSH 协议与行为不变，不新增运行时依赖。
