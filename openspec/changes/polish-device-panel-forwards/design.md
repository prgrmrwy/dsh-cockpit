## Context

见 `proposal.md` 的 Why。当前实现的相关约束（读代码得到，决定都建立在这些事实上）：

- 设备卡片是两列网格（`.device-card { grid-template-columns: minmax(0,1fr) auto }`），右列是设备操作组 `.device-card-actions`（`display:flex; align-items:center`）——它在被拉伸的行高里**垂直居中**，于是卡片一高就浮在中间。
- 转发区 `.forward-list` 在左列文案流里，用 `border-top` 与上文分隔；每条 `.forward-row` 自己是 `border + border-radius + background: var(--surface-raised)` 的卡片，而它所在的设备卡片同样是 `border + border-radius + background` —— 双层盒子。
- 创建表单 `.forward-form` 是裸的 `label + input` 加一个未加类名的 `button`，靠 `align-items: flex-end` 对齐；失败说明 `.panel-error` 用 `flex-basis: 100%` 换行。
- 两个界面（DSH 设置区块、驾驶舱面板）共享同一份数据模型，但**不需要**共享同一套呈现：DSH 区块是只读远观，面板是就地的读写现场。

## Goals / Non-Goals

**Goals**

- 让使用者一眼看出「转发区」与「创建区」是两个各自成形的分组，并且创建区就在转发区旁边（同一张卡片内，不跳转、不折叠）。
- 消除双层盒子，让行与行之间靠分隔线与列对齐形成秩序。
- 让设备操作组回到它该在的位置（与标题齐平），不再随卡片高度漂移。
- 零行为变更：数据、端点、事件流、确认与错误处理全部不动。

**Non-Goals**

- 不动 DSH 设置页区块（它在 `device-forward-registry` 里刚定稿，本次不改）。
- 不在面板放八格占用计（见 D4）。
- 不重排设备卡片的信息层级（标题 / 标识 / 认证摘要的顺序不变）。
- 不引入新组件库、图标或动画。

## Decisions

### D1 转发区：一个分组 + 一张列表，而不是「卡片里套卡片」

区头保留「转发」与 `N / 8`；其下是一张列表：行之间 `border-top: 1px solid var(--border)`，**去掉每行的独立边框、圆角与背景**。每行是「摘要行 + 操作行」：摘要行 `flex-wrap` 排列端口 / 地址 / 状态 / 类型 / pid，每个字段 `white-space: nowrap`（值内部永不断行，放不下就整体换到下一行）；`删除` 属于该行的操作行，与标签、持有者同一行、`margin-left: auto` 贴右。

- 备选：统一列宽模板（端口 / 地址 / 状态 / 类型 / pid）让相邻行同字段严格对齐（**实测否决**）。在 1440×1000 视口下设备卡片左列（`.device-card-main`）只有 344px、转发行宽 323px：6 列模板算出 `54px 72px 54px 72px 20.6px 0px`——地址被压到 6em 下限后折成两行、`pid 89336` 被压成 20px 宽（单字竖排）、删除列直接归零。同视口下卡片右列的设备操作组占 264px，这是面板两列布局的既有宽度预算，不在本 change 可改范围。

- 备选：保留行卡片但把设备卡片背景改成非卡片（否决——设备卡片是列表项本身，去掉它的边框会让卡片与列表容器糊在一起）。
- 备选：把转发清单移出卡片、做成展开区（否决——它在卡片里才有「这台设备的」归属，移出去反而增加跳转成本）。

### D2 创建区：带标题与说明的分组，而不是散落的控件

创建分组就是 `form` 本身（`aria-labelledby` 指向组内标题，从而获得可访问名，避免 `section` 包 `form` 的多余嵌套）包含：标题「添加常驻转发」、一句说明（常驻条目在驾驶舱重启后仍保留；设备上的组件申请的是「随持有者」条目，随持有者释放即回收）、两个字段（`设备端口` 用 `inputMode="numeric"`、输入框固定 6.5em；`标签（可选）` 输入框撑满剩余宽度）、以及独立一行的主按钮。字段名与输入框同行，字段名 `min-width: 6.5em` 让两个输入框左边缘对齐。失败说明渲染在该 `form` 内。

- 备选：把创建挪进弹窗或折叠区（否决——增删是这张卡片的主任务，藏起来只会让「怎么加」重新变成问题）。
- 备选：保留 `label` 在输入之上（保持现状）（否决——标题 + 说明已经把语义说清楚，字段名改为行内标签更省高度、也让字段名与输入框对齐成一列）。
- 备选：三件套（端口 / 标签 / 按钮）挤在一行（否决——同一张卡片的内容列实测只有 323px，一行放不下，会退化成输入框被压到几十像素；两行字段 + 独立按钮行在任何卡片宽度下都成立）。

### D3 对齐：卡片两列顶部对齐，操作组与标题齐平

`align-items: start`（或等价的 `align-self`）落在卡片网格上，让操作组贴着标题行。删除/禁用是设备级动作，仍留在右列，不与转发区的写操作混排。

- 备选：把操作组移到卡片底部（否决——底部紧邻转发区，容易把「删除设备」与「删除转发」误读为同一层级）。

### D4 面板不放八格占用计

DSH 设置区块的占用计是为了在**看不见面板的地方**让上限可感；面板里用户就站在管理现场，`N / 8` 文本已经足够，并且行内空间要留给端口/地址/诊断。这是**有意的不一致**，写在这里避免以后被「统一」掉。

### D5 保持可访问名与 DOM 钩子

分组用 `form` / `section` + `aria-labelledby`，不改变现有可访问名（`添加常驻转发`、`删除转发 <port>`、`<displayName> 操作`、`<displayName> 转发`）与 `data-forward*` 属性；`forward-panel.test.tsx` 断言的文本与角色保持可用，只更新依赖旧结构（行卡片 class、表单 class）的断言。设备操作组的 `aria-label` 原本落在无 role 的 `div` 上（对辅助技术不可见），本次补 `role="group"` 让它真正成为可访问名——名称本身不变，只是变得可用。

### D6 令牌与窄屏

只用既有令牌：`--border` / `--surface-raised`（仅用于仍需要底色的元素，如类型徽标与主按钮）/ `--fg` / `--fg-dim` / `--accent-soft` / `--danger-soft` / `--ok` / `--warn` / `--error` / `--focus-ring`。窄屏沿用现有断点：`860px` 时卡片单列、`520px` 时操作组两列换行、主按钮撑满一行。转发行的折行不依赖断点——字段 `nowrap` + 容器 `flex-wrap` + `min-width: 0` 让它在任何宽度下都整体折行、不横向溢出，因此没有「窄屏专用列模板」需要维护。

## Risks / Trade-offs

- **测试选择器**：`forward-panel.test.tsx` 现有断言以文本/角色为主，但可能引用 `.forward-row` 的网格行为；`styles.test.ts` 直接断言 CSS 规则，本次会命中若干条既有断言（需要同步更新，不能靠删断言过关）。
- **对齐 vs 生存**：固定列模板能让同行字段严格对齐，但在 323px 行宽下会把值压成竖排（已实测）。本 change 选择「字段整体折行」保证任何宽度都读得出来，代价是列对齐只在字段宽度相近时自然成立。
- **与 DSH 区块的差异**（占用计、说明文案）是有意为之，记录在 D4，避免后人为了「一致」把两者强行对齐。
- **不改行为**是本 change 的护栏：任何需要改端点、投影或事件流的做法都超出范围，应另开 change。
